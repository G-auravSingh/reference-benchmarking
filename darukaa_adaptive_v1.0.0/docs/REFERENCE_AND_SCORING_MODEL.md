# Darukaa adaptive reference and scoring model

## 1. Universal score architecture

The adaptive framework uses the same scoring architecture across terrestrial, aquatic and other ecosystem profiles, regardless of whether an indicator originates from Earth observation, acoustics, field surveys, eDNA or another validated observation source.

For each applicable indicator:

`Raw value → reference comparison → intactness (0–100) → concern level`

Indicators are then grouped into four common pillars:

- **C1 — Extent**
- **C2 — Vegetation**
- **C3 — Fauna**
- **C4 — Pressure**

The pillar score is the geometric mean of the eligible indicator intactness scores in that pillar.

The overall **State of Nature (SoN)** is the geometric mean of the four pillar scores when the required pillar coverage is met.

Concern labels are assigned only after the continuous score has been calculated. Labels are never averaged.

## 2. Fixed Darukaa concern convention

These bands are a declared Darukaa product convention, not a claim of universal ecological thresholds.

| Intactness score | Concern |
|---:|---|
| 80–100% | Very Low |
| 60–<80% | Low |
| 40–<60% | Moderate |
| 20–<40% | High |
| 0–<20% | Very High |

The same bands are used for indicator, pillar and overall scores.

## 3. Reference comparison

A scoreable indicator requires a comparable reference value or reference distribution.

Reference priority is:

1. **Tier-1** — externally justified / supplied reference.
2. **Tier-2** — candidate regional/context reference generated by the profile.
3. No approved reference — raw value may still be reported and benchmarked, but the indicator is not scoreable.

Reference availability and approval are separate. A benchmark can be visible in the output without being authorized to influence the ecological score.

### Direction-specific intactness

The raw value is not interpreted with one universal ratio. The registry declares how the metric should be compared.

**Higher-is-better**
`intactness = min(1, observed / reference)`

**Lower-is-better**
`intactness = min(1, reference / observed)`

**Reference-target**
`intactness = max(0, 1 - abs(observed - reference) / abs(reference))`

The reference-target form is reserved for metrics where both upward and downward departures from a comparable reference represent departure from the desired reference condition.

The bounded result is multiplied by 100 to produce the indicator intactness score.

## 4. Metric concern

Once intactness is available, the fixed five bands assign the concern level.

Example:

`observed = 40`, `reference = 50`, higher-is-better`

`intactness = 0.80 → 80% → Very Low concern`

The raw value and reference remain in the scorecard so that the label is auditable.

## 5. Pillar aggregation

For each pillar:

`Pillar score = geometric mean(indicator intactness scores)`

This is deliberately calculated on the continuous 0–100 scale.

The system also identifies:

`limiting indicator = scoreable indicator with the lowest intactness`

Example:

> C1: 62% (Low concern) — limited primarily by `surface_algal_bloom_frequency` at 31%.

The limiting indicator is explanatory; it is not a second competing pillar score.

## 6. Overall State of Nature

When all four required pillars are represented:

`SoN = geometric mean(C1, C2, C3, C4)`

Then the overall 0–100 score receives the same five-band concern label.

The system identifies both:

- the **limiting pillar** (lowest pillar intactness);
- the **limiting indicator within that pillar**.

Example format:

> Overall SoN: 51% (Moderate) — limited primarily by C3 Fauna (34%), itself limited by `bii` (8%).

No concern labels are averaged and no metric is assigned a numeric score merely because it belongs to a pillar.

## 7. Field, acoustic and terrestrial metrics

The scoring engine is intentionally not restricted to the aquatic registry.

Field/acoustic/terrestrial observations can enter through the generic external-observation interface with:

`metric, pillar, raw_value, direction, reference_value`

and optional:

`units, reference_type, reference_level, reference_approved_for_scoring, status, notes`

This allows metrics such as species richness, fauna abundance, acoustic diversity, vegetation condition, habitat extent, BII/MSA or project-specific field measures to use the same scoring machinery once their reference and direction are defined.

The calculation of those metrics remains in the relevant domain module. The scoring engine only consumes the measured value plus its metadata.

## 8. Evidence boundaries

A metric may be:

- reportable but not referenceable;
- referenceable but not approved for scoring;
- scoreable at indicator level while the overall SoN remains withheld because one or more required pillars are not represented.

For example, a lake EO run can produce water extent and water-quality proxies, but it cannot create local fauna evidence. C3 must therefore be populated by appropriate biodiversity observations before a four-pillar SoN composite can be reported.

## 9. Transparency requirements

Every scorecard should retain:

- raw value;
- reference value;
- reference level;
- raw relative comparison;
- intactness score;
- concern level;
- pillar;
- scoring method;
- score eligibility;
- status/QA fields;
- limiting indicator at pillar level;
- limiting pillar and limiting indicator at overall level.

This provides one continuous scoring system while keeping the evidence chain visible.
